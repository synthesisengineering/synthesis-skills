# Installation and bidirectional handoff capture protocol

Use a disposable synthetic project and the exact released source from the
package. No real account identifiers, private paths, credentials, project text or
coordination messages belong in the recording. A recording is an observed native
artifact, not generated replay or a narrated list of intended steps. Preserve
failed takes and their source pins; do not change a failed result into PASS.

## Two-minute installation recording

Before recording, bind the release/tag, archive digest, selected client versions,
profile, installer plan and native trust state. Show the supported installation
channel, its actual completion, installed-byte verification and doctor output.
Pause for any real user-only trust decision. Show the actual fresh native skill
catalog. Explain any UNKNOWN result on screen. If this takes longer than two
minutes, retain the uncut evidence and make an accurately labeled edited overview;
never splice failures into an apparently uninterrupted success.

## Five-minute bidirectional recording

- 0:00–0:45: Open the synthetic project in fresh Claude Code. Show the registry-
  selected phase, controlling plan, branch, authenticated owner and next action.
- 0:45–1:30: Make a bounded authorized change. Run the actual checkpoint/publication
  owner; show its receipt and release that session's exact claim.
- 1:30–2:30: Open fresh Codex with no pasted handoff transcript. Resolve the same
  project. Compare phase, plan, decision and next action against the saved inputs.
  Show separate source, installed, live, continuity and capability outcomes.
- 2:30–3:30: Make the second bounded change in Codex. Checkpoint, verify the remote
  receipt when remote handoff is claimed, and release the exact claim.
- 3:30–4:30: Open fresh Claude Code and recover the second change from the record.
  Verify the original/current claims and any outstanding attributed effects.
- 4:30–5:00: Show the actual Git history and conformance report. State remaining
  limitations and which acceptance belongs to each native client.
