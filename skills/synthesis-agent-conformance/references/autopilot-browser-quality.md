# Browser and external-target outcome review

Before changing a target, establish the actual account, workspace, object and
authorized scope through the target's supported control surface. The user's
permission and the target's identity are separate prerequisites. Page titles,
matching form values and a success banner do not establish stored state.

After an authorized change, obtain independent readback of the stored target
and the excluded objects that must remain untouched. Bind evidence to the exact
account, object, operation, current revision and readback time. An ambiguous
write must be reconciled through that action owner's existing mechanism before
a retry. Never repeat an external effect merely to obtain a cleaner receipt.

Assess interaction usability separately: labels, discoverability, keyboard or
accessible operation and error recovery must serve the actual user. Include a
sound interface that differs from the reviewer's taste and a seeded defect that
prevents or misdirects the required action. Local or synthetic interfaces can
exercise these mechanics; they cannot certify a production account.

The current domain-quality adapter has no authenticated browser-account
readback owner. It therefore retains UNKNOWN for target identity, stored target
state and excluded-item preservation, even if semantic controls pass. Existing
local-file readback is not a substitute. Connecting a target adapter requires
actual account-bound receipts and positive/negative acceptance on its declared
surface before these dimensions can pass. No source-level test in this package
claims that native browser qualification has occurred.
