# Vendor review and directory evidence packages

Use the existing verified `synthesis exec-public` owner to invoke
`synthesis-agent-conformance/scripts/vendor_bundle.py prepare`. Supply an exact
source root, JSON request and new output archive. The request contains schema 1,
one supported vendor (`openai`, `anthropic`, `hermes`), the exact draft, native
receipt paths keyed by required client, and captured official-source records.
Each source record binds its HTTPS URL, SHA-256, observed UTC timestamp and local
UTF-8 capture path. Captured text is public documentation; private receipt paths
and raw native histories are never exported.

The builder runs the actual source-conformance owner within the existing finite
process owner, checks both plugin manifests, licenses, support and governance,
refuses placeholders, and closes the complete source inventory before and after
collection. Optional `--verify-release` reads only the public GitHub release and
source archive through normal TLS, then compares every source byte and executable
mode. It does not install anything or use a provider/account. Missing, changed,
stale, foreign or unverified native receipts remain UNKNOWN. Hermes currently
has no accepted native live-receipt owner; source observations cannot substitute.
The default builder does not launch native clients. Explicit `--verify-native`
requires a separately authorized native query and `qualification_scope` containing
absolute repo_root, project, active_project_file and coordination_board paths. It
invokes the existing local hook-trust, catalog and continuity owners under finite
process custody. Missing, failed or unrequested outcomes cannot make readiness
green. This author package has not executed those native queries.

A later published release is reconciled by rebuilding from its exact bytes and
fresh owner evidence, never by changing a status field in the old archive.

Default draft archives exclude source bytes, local source filenames and incidental
source-check names. A source-directory digest never grants disclosure eligibility.
A full-source archive requires explicit `--verify-release`: the export owner
rechecks the actual public release archive against the complete source inventory
before opening the destination. Untracked local material therefore prevents a
full-source archive; a forged release PASS field cannot authorize one. The
default metadata-only draft remains usable without network access.

The archive contains exact unsent text, captured official documentation,
source check outcomes and sanitized aggregate evidence results; source bytes are
included only in a freshly verified public-release export. Unsigned transcript
metadata cannot establish native acceptance. Optional `--portable-context`
selects explicit local envelope, trust and current-binding paths per client
through the reviewed signed-observation owner. Its signature result is retained
in a separate plane, never promoted to native acceptance or sending authority.
The native callback gate accepts only the owner-bound observation described below.
Other native evidence remains UNKNOWN. This package creates no trust anchor or signing key. ZIP verification
checks custody only; it expressly requires native revalidation. A retained
technical status is not fresh proof and neither preparation nor verification
grants contact or submission permission. Partial failed exports remain evidence
and must not be presented as completed packages.

## Current channels

- OpenAI: [Claude-plugin submission](https://developers.openai.com/plugins/guides/submit-claude-plugin).
  The documented skill-only path accepts a Claude plugin archive and converts its
  manifest. A Codex hook requires its own runtime and trust; Claude trust does
  not transfer. Ordinary ChatGPT skill use does not establish Codex hook behavior.
- Anthropic: [publish a plugin](https://code.claude.com/docs/en/plugins/publish).
  The developer directory portal and the official Claude Code marketplace are
  different channels. Directory validation is not an official-marketplace
  endorsement or a promise of acceptance.
- Hermes: [contribution guidance](https://github.com/NousResearch/hermes-agent/blob/28e6496a5e3adfea57bebfc9571b981bff378523/CONTRIBUTING.md).
  Present a bounded CLI pilot for maintainer review. Specialized skill sharing
  belongs in the documented skills hub/registry channel; do not assume a Synthesis
  package is approved, installed, or listed there.

These routes were checked September 27, 2026. Re-read their exact current rules
when preparing an outward submission. A GitHub issue being open is tracker state,
not proof of current reproduction or attribution of a defect to its vendor.

## Directory completion and the demonstration

A technical review package is not a completed directory submission. Preserve
separate receipts for the following original requirements:

1. Source conformance, exact released manifests/license and current support and
   security statements; do not promise service levels absent from SUPPORT.md.
2. Fresh installed, live, continuity and outcome evidence for each claimed client,
   plus the actual catalog budget. A source-only catalog count is insufficient.
3. A two-minute installation recording and a five-minute bidirectional handoff
   recording, reviewed for privacy and bound to the exact source release.
4. The exact final outward text, recipient/channel and approval. Code publication
   approval is not permission to contact a vendor or submit a directory entry.

The builder deliberately reports directory recordings as not attached and
submission as not authorized. The actual capture and submission owners must
complete these external actions; writing a PASS field is not a substitute.
Use the [capture protocol](vendor-demo-protocol.md) for the two recordings.


## Admitted callback evidence

`prepare --native-context <file>` accepts an explicit per-client selection, not a
status assertion. Each selected client requires exactly `project`, `run_id`,
`actor`, `source_handle`, `source_generation`, `event_ids` and `registry_latest`.
The three event IDs select the paired SessionStart hook start, hook response and
successful terminal event (Claude) or actual ephemeral thread response (Codex)
from one admitted native worker. The existing PM
admission, execution journal, native-worker receipt and observation bridge must
all revalidate their current authority and captured raw bytes. A signed portable
observation or a local registry file by itself cannot satisfy this interface.

The implemented routes are Claude's print-stream SessionStart callback and
Codex's model-free app-server callback observation.

The context producer commits its existing outcome record with exact installed
and execution-tree generation digests, then emits one final digest witness in
the native hook's output. The consumer joins that native output to the exact
registry event, current source release, installation, execution tree and
admitted generation. It requires complete bounded stream coverage, an enforced
worker permission boundary, matching hook and session identities, successful
outcomes, and receipt/ingestion freshness within five minutes. It revalidates
source, admission and custody before returning the result. The outcome byte
count describes context before the witness, whose bytes are separately bounded.

A PASS here means **admitted CLI SessionStart context delivery** only. It does
not establish the running desktop's live loading, all-hook coverage, recovery,
model quality, vendor approval, or permission to publish or contact anyone.
The source regression uses a synthetic producer under the real local sandbox
and real admission/storage consumers; it is not a native client acceptance run.
An actual owner must separately admit a real launch and then supply its current
observed source selection. This builder launches no client.

Codex uses the existing `native-cli` worker admission with the exclusive
`native-callback` capability. It sends only initialize, initialized and an
explicit ephemeral thread/start; it never submits a model turn, resumes an
existing chat or creates a persistent user-facing task. The actual reply must
confirm the same selected model/effort, confined workspace policy, ephemeral
identity, no parent/project/history path and no turns. The finite process owner
retains exact incoming and outgoing frames and reaps its owned group. Typed
hook/started and hook/completed entries establish delivered context, not command
stdout or an invented exit code. The selected pair must identify the current
plugin's hooks file, complete successfully and contain the exact registry
witness. `hooks/list` alone still proves neither execution nor delivery.

An ephemeral hook can record an inert `codex-callback-candidate` in the existing
receipt registry under the worker's explicit observation hint. That hint is not
native trust. Candidate records never update latest/live-load pointers or issue
signed native observations, and ordinary missing-transcript probes still refuse.
Only the fresh admitted worker transport and exact registry/source/generation
join can qualify the scoped callback result. A callback PASS explicitly records
`model_turn_completed: false` and leaves native recovery UNKNOWN. Existing
client hook trust and selected-client configuration are never copied or altered.
The regression suite substitutes only a confined synthetic producer; actual
installation and native qualification remain separate required steps.

Muse's current pinned MSP export has no qualified hook-run result grammar. Its
existing opaque hook projections remain observations, not a result-output,
session and installed-source join. The observed view/subscribe refusal is not
repaired by guessing fields or retrying an unchanged launch. Hermes supplies
context through pre_llm_call; its on_session_start is an observer whose return
value is ignored. A fresh provider-request observation could witness consumed
context, but the admitted native-worker capture and registry join for that
surface are still unfinished engineering. A local SQLite/source observation or
hand-written PASS cannot replace that transport. These requirements remain open;
no Claude or Codex result transfers to another client, and no paid provider turn
is implied by source support.
