# The first useful task

A first-time user who installed from a marketplace gets skills with no orientation, and
found them "a bit suspect" for it (lesson 2026-09-23, the shared install path is the
product). After setup, help them get one useful result in their own work.

Start with the result the user wants. Ask only for the intended result and the actual
clients needed for it. Use plain language before explaining repository or profile terms.
A nondeveloper can choose any of these:

| Journey | First task | Existing owners |
|---|---|---|
| Portable project | Save a project plan and checkpointed handoff | Project management, context lifecycle, checkpoint, conformance |
| Engineering | Save a source-grounded implementation plan | Portable project plus code planning, preflight, integrity, review, repository guards |
| Writing | Save a review or revision of a supplied draft | Portable project plus article writing, link research, craft, quality, voice profiling |
| Work management | Save a daily plan from supplied priorities | Portable project plus rituals, catch-up, inbox, absence, chief-of-staff methods |
| Organization | Save a plan grounded in a supplied organization manifest | Portable project plus onboarding, knowledge management, disclosure and guardrails |

Then:

1. Load the skill the journey names in the person's harness and do one task they
   supply. Never invent a participant, profile, meeting history, private voice or
   organization configuration; missing integrations stay explicit.
2. Save the artifact where they can see it (a project's `resources/artifacts/` when
   the work belongs to a project) and show it to them.
3. Keep what they said about its usefulness separate from what was verified: the file
   exists with these bytes; whether it helped is theirs to say.
