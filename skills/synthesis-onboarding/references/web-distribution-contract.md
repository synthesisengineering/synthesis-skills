# Web distribution contract

The website imports `release-capabilities.json`; it must never infer publication from a package directory or a successful local build. `distribution.schema_version` is 1. Pending records remain non-executable in previews; the website's release gate requires verified routes for every current component and channel. AUR is excluded by user direction.

`official_npm_scopes` admits the selected publisher scope. `official_npm_packages` admits only the verified unscoped `ownwords` package. Component names and binaries are fixed: full/skills-only/modular use `synthesis`; SlopCheck uses `slopcheck`; Console uses `synthesis-console` (npm package `console`); Ownwords uses `ownwords`. Package-manager installation never implicitly activates setup. Commands are derived from these validated identities, followed by an explicit `BINARY setup`.

Each `distribution.components` entry (`slopcheck`, `console`, `ownwords`) contains its canonical HTTPS GitHub `repository`, `binary`, `core_staging` object (`supported: true`, `opt_out_argument: --no-dormant-core`), and channel records. `brew`, `npm`, and `bun` records use `status`, `package`, `platforms`, and `evidence_url`. Only status `verified` enables copying an install command. The brew tap is `synthesisengineering/tap`.

Tool `curl` and `source` records require `status`, numeric `release`, `artifact_url`, SHA-256 `sha256`, and `source_url`. Artifacts must belong to the component's canonical repository under `releases/download/vVERSION/`. The curl artifact ends in `.sh`; source provides a release archive. Source URLs identify that same version under `tree/vVERSION` or `blob/vVERSION/`. The UI derives curl execution and exact-tag Git acquisition; it never executes arbitrary command strings stored in release metadata. The tool installer must bind its own download/dependency chain to verified bytes. The checksum is displayed beside direct downloads and terminal routes.

`distribution.modular` contains `status`, `release`, `inventory_source`, `skills`, and `default_skill`. The skill list is copied from the release's `skills/synthesis-onboarding/references/components.json` inventory, never invented for presentation. A verified modular record must name the same release as the bootstrap. Only skills in this list can form commands. Selection produces `synthesis setup --profile modular --skill NAME`; optional staging opt-out adds `--no-dormant-core`. Tool setup exposes the same opt-out. Dormant payloads consume download bandwidth and disk storage but do not register hooks, instructions, services, or client-discoverable skills.

The system bootstrap uses an immutable raw GitHub URL and explicit release pin. Its short URL becomes an executable default only after `short_url_verified` is true following an ordinary live-URL byte comparison. Missing, pending, malformed, or foreign evidence must not be represented as a working released route.
